# Entrega del Asistente IA para Docentes — 13 de octubre de 2026

Se amplió la base Next.js/React/TypeScript y NestJS existente. Se conservan autenticación, fuentes, RAG con pgvector, conversaciones, clases, sílabos, evaluaciones y presentaciones; no se incorporan funciones de aula virtual.

## Funciones añadidas

- Guías didácticas con una solicitud principal, ocho tipos, recursos visuales, opciones avanzadas ocultas y plantillas opcionales. Adaptación del contenido mediante contexto académico y prompts por disciplina.
- Gu?as terminadas sin editor: portada, apartados desarrollados, dise?o inspirado en colores y tipograf?a de la referencia, vista del PDF final y descargas PDF/Word. Cantidad de 2 a 30 p?ginas incluida la portada; contenido y maquetaci?n verificados antes de guardar.
- Imágenes propias privadas: validación, decodificación, normalización, límite de píxeles, tamaño y cuota. Inserción, reemplazo, eliminación del documento, ancho y pie de imagen; proporciones conservadas al exportar. La generación IA usa exclusivamente `GEMINI_IMAGE_MODEL`; si falta, el documento continúa con texto, tablas y diagramas.
- Planificación desde sumilla, sílabo guardado/documentos o creación manual. Unidades y semanas editables, reordenación, regeneración de una semana, distribución de horas y creación de sesiones, guías, presentaciones y evaluaciones con datos transferidos.
- Contexto académico opcional: país, tipo de institución, facultad, carrera, especialidad, nivel, área, modalidad y pedagogía; el nombre e institución siguen en el perfil. La carga inicial ya no puede sobrescribir cambios rápidos del docente.
- Plantillas PDF/DOCX analizadas y guardadas: secciones, campos, tablas y notas. Selección sin volver a subir, modos estructura/inspiración, separación respecto de fuentes temáticas y copia de la referencia en el material generado.
- Fuentes: clasificación, desactivación y formulario de enlaces web. RAG rechaza fuentes desactivadas y plantillas usadas como contenido.
- Recuperación de contraseña mediante un puente de correo: tokens aleatorios guardados como hash, caducidad de 30 minutos, un solo uso y revocación de sesiones. El formulario informa cuando falta configurar correo.
- Kahoot: XLSX construido sobre el archivo oficial descargado, validación de 120 caracteres por pregunta, 75 por respuesta, 2–4 opciones y tiempos admitidos. Instrucciones de importación manual. Se conserva Quizizz/Wayground.
- Banco de preguntas y sesiones tienen rutas independientes; el examen desde banco reutiliza preguntas existentes sin regenerarlas. Word, PDF, variantes A/B y solucionario están disponibles.
- Sesiones: imágenes propias, regeneración de apartados, evidencias y bibliografía opcionales; exportación con seis secciones académicas. Las exportaciones de planificación presentan cada semana en tablas.
- Dashboard con contadores reales de guías, sesiones y presentaciones; historial con acceso al editor completo y restauración de versiones.
- Concurrencia IA limitada por proceso, cuota por docente y consumo registrado. Dockerfiles y Compose para un VPS compartido.

## Migración aplicada

`npm run migrate` se ejecutó sobre la base PGlite local existente. El esquema es aditivo e idempotente:

- `users.academic_context`.
- Categoría y estado habilitado en documentos.
- `institutional_templates`, `password_resets`, `visual_assets` y `stored_files`.
- Referencia y copia de estructura de plantilla en materiales generados.

No se eliminaron tablas ni registros. Antes de activar Cloudinary se registró el almacenamiento local de los archivos existentes. `stored_files` conserva el proveedor de cada original: las cargas nuevas usan Cloudinary y los originales antiguos siguen descargándose desde disco. `LEGACY_STORAGE_DRIVER=local` conserva esa información al repetir migraciones. Para una base antigua que utilizase S3, establecer su proveedor anterior explícitamente antes de migrar.

## Integraciones comprobadas

**Gemini real:** cuatro solicitudes sintéticas de guías (Sistemas, Enfermería, Derecho y Contabilidad), validadas y exportadas a DOCX/PDF; planificación de dos semanas con horas validadas. Evidencia: `artifacts/gemini-platform-check.txt`. No se enviaron documentos personales.

**Cloudinary real:** subida privada, descarga mediante URL firmada en el servidor, comprobación de bytes y eliminación del archivo sintético. Evidencia: `artifacts/cloudinary-check.txt`. Activado en la configuración local para archivos nuevos. Las credenciales permanecen en archivos ignorados y nunca se entregan al navegador.

**Kahoot:** estructura contrastada con la [ayuda oficial](https://support.kahoot.com/hc/en-us/articles/115002812547-How-to-import-questions-from-a-spreadsheet-to-your-kahoot) y su plantilla descargada el 13 de octubre de 2026. La importación en una cuenta de Kahoot la realiza el docente; no se afirma haber publicado un quiz ni probado esa cuenta externa.

## Configuración pendiente y límites

1. **Correo:** faltan `MAIL_DELIVERY_URL` y `MAIL_DELIVERY_TOKEN`. El endpoint HTTPS debe aceptar `{to,subject,text}` con Bearer y confirmar entrega con HTTP 2xx. Se comprobaron los tokens y la revocación; no se verificó una entrega real de correo.
2. **Imágenes IA:** falta `GEMINI_IMAGE_MODEL` compatible con salida de imágenes para esta cuenta. No se generaron imágenes IA reales; funcionan las imágenes propias y los diagramas. Configurarlo no garantiza disponibilidad: las respuestas se comprueban y los fallos se informan.
3. **Producción:** falta `SCAN_URL`; las cargas se rechazan en producción hasta conectar un escáner que devuelva `{clean:true}`. No se afirma realizar antivirus en desarrollo.
4. **Plantillas:** se conserva una estructura editable reconstruida, no el diseño exacto del Word/PDF original. Las tablas y el contenido exportado son editables. No se promete reproducción visual idéntica.
5. **PDF escaneado:** el extractor utiliza texto seleccionable. Las imágenes cargadas como fuentes pueden transcribirse con Gemini. No se añadió OCR multipágina a PDF sin capa de texto.
6. **Ejemplos institucionales:** los archivos UNICA y la guía Spring mencionados en el prompt no se adjuntaron en esta solicitud. Pueden incorporarse desde Plantillas y lineamientos; no se presenta una adaptación contra archivos que no se recibieron.
7. **Publicación:** el VPS y su proxy/certificado no se configuraron. PostgreSQL externo queda preparado, pero la comprobación local usó PGlite con pgvector; no se ejecutó una migración sobre una base remota.
8. **Dependencias del frontend:** la auditoría detectó ocho entradas heredadas: herramientas ESLint/glob con un aviso de `braces` sin versión corregida publicada y dependencias del visor PPTX (`echarts`, `uuid`). No se degradó Next.js ni se sustituyó el visor funcionando para ocultar estos avisos. El visor ya ejecuta su código en un iframe sin acceso al origen de la aplicación, con CSP que bloquea conexiones externas; esto reduce el alcance, no equivale a una corrección de la dependencia. Revisar actualizaciones del proveedor antes de publicar. La auditoría del backend sí quedó en cero.

## Despliegue en VPS

Mantener el proyecto como frontend y backend modular, una base PostgreSQL y los servicios externos; no necesita Kubernetes ni contenedores por agente.

```bash
cp .env.deploy.example .env.deploy
# Editar .env.deploy: origen HTTPS, contraseña PostgreSQL aleatoria,
# Gemini, Cloudinary y SCAN_URL. Correo/imágenes son opcionales.
docker compose --env-file .env.deploy -f compose.vps.yaml build
docker compose --env-file .env.deploy -f compose.vps.yaml up -d postgres
docker compose --env-file .env.deploy -f compose.vps.yaml run --rm backend node dist/database/migrate.js
docker compose --env-file .env.deploy -f compose.vps.yaml up -d
```

Configurar el proxy HTTPS hacia `127.0.0.1:3010` y usar exactamente ese dominio en `APP_ORIGIN`. PostgreSQL y la API no publican puertos al exterior. Preparar `backend/storage` con permisos para UID 1000 si se usa la caché de fotografías o se trasladan originales locales; mantener los registros de `stored_files` junto con esos archivos. Los límites de RAM/CPU son iniciales: ajustarlos a la memoria disponible del VPS y monitorizar antes de aumentar concurrencia. Hacer copias de la base y originales antes de trasladar datos existentes.

Las generaciones detalladas pueden durar más de 30 segundos. Next.js utiliza `experimental.proxyTimeout=600000` para mantener la conexión con NestJS. En Nginx configurar `proxy_read_timeout 600s`, `proxy_send_timeout 600s` y `client_max_body_size 55m` en la ubicación que reenvía a la aplicación, para evitar que el proxy externo corte antes la solicitud.

`PRESENTATION_IMAGES=off` evita consultas a Wikimedia en el ejemplo de producción; puede habilitarse según los requisitos de conectividad. Nunca versionar `.env.deploy` ni copiar claves a variables `NEXT_PUBLIC_*`.
